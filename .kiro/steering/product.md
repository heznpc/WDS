# WDS 제품 논지

## 무엇을 해결하는가

사람이 프롬프트를 칠 때 감정 때문에 섞여 들어가는, 요청의 정보에는 기여하지 않는 어휘를 전송 전에 사용자 승인 하에 정확히 한 구간만 지운다.

**핵심 논지는 토큰 절감이 아니다.** 요청과 무관한 어휘가 들어가면 모델이 사용자 의도를 잘못 파악해서 **결과가 틀어지는 것**이 문제다. `씨발 이 파서 고쳐줘`의 실패 모드는 토큰 4개 낭비가 아니라, 모델이 요청 대신 감정을 처리하는 것이다. 거절, 달래기, 방어적 응답, 톤 미러링. 원하는 답이 안 나와서 다시 물어야 하므로 실제 낭비는 왕복에서 발생한다.

멘탈 모델은 **아이폰 자동완성의 역방향**이다. 자동수정이 존재하는 이유는 맞게 치는 게 불가능해서가 아니라 사람이 그 순간에 안정적으로 못 하기 때문이고, 감정적으로 치는 순간은 자기통제가 가장 안 되는 순간이다. "그냥 안 치면 되잖아"는 "그냥 맞게 쓰면 되잖아"와 같은 논리다.

애니메이션(부수기 오버레이)은 바이럴용이다. 기능의 본질이 아니다.

## 이 제품이 아닌 것

- 검열 도구가 아니다. 사용자를 교정하지 않는다.
- 말버릇 교정 도구가 아니다. 욕설 습관을 고치려는 게 아니다.
- 말버릇 프로파일을 학습하지 않는다. 무상태·무학습이다.
- 토큰 비용 절감 상품이 아니다. 사용자는 정액 구독으로 쓰므로 입력 토큰 절감의 금전적 가치는 0이다. 이 근거로 포지셔닝하면 안 된다.
- prompt enhancer가 아니다. rewrite하지 않고 삭제만 한다. 원문 의미는 불변이다.

## 근거를 어디에 두어야 하는가

"무례하면 응답 품질이 떨어진다"는 문헌은 **서로 모순된다.** 이걸로 주장하면 반례에 찔린다.

- [arXiv 2402.14531](https://arxiv.org/abs/2402.14531) — 무례한 프롬프트가 성능 저하 경향, 단 최적 정중함은 언어별로 다름
- [arXiv 2510.04950](https://arxiv.org/abs/2510.04950) — 정반대. 무례한 쪽이 더 정확했음 (80.8% vs 84.8%)
- [arXiv 2512.12812](https://arxiv.org/abs/2512.12812) — 유의성은 일부 인문 과제에서만, Gemini는 톤에 둔감

반면 **"과제와 무관한 내용이 추론을 오염시킨다"** 쪽은 방향이 일치한다. 프레이밍을 정중함(politeness)이 아니라 무관성(irrelevance)에 두면 방어 가능하다.

- [arXiv 2302.00093](https://ar5iv.labs.arxiv.org/html/2302.00093) — 무관한 정보를 끼우면 성능이 급격히 하락 (기준 논문)
- [arXiv 2502.01609](https://arxiv.org/html/2502.01609v1) — 자연스럽지만 과제와 무관한 문맥이 일관된 성능을 깨뜨림
- [arXiv 2505.18761](https://arxiv.org/html/2505.18761) — 추론 경로 선택 자체에 영향
- [arXiv 2504.01201](https://arxiv.org/html/2504.01201) — 의료 도메인에서 정확도 최대 17.9% 하락
- [arXiv 2605.30913](https://arxiv.org/html/2605.30913v1) — 독성 어휘 교란이 사실 정확도를 일관되게 떨어뜨리고 불확실성 증가
- [arXiv 2510.08158](https://arxiv.org/html/2510.08158v1) — 위험해 보이는 단어 때문에 **무해한 요청이 거절됨**. 욕설에 가장 직접적인 메커니즘
- [researchSquare rs-9786387](https://www.researchsquare.com/article/rs-9786387/v1.pdf?c=1781301645000) — 위협적 톤에서 정확도 1.5% 하락, 방어적 응답 52.9% 증가

안전한 표현: "톤에 끌려가지 않게 한다", "의도가 그대로 전달되게 한다".
과한 표현: "응답 품질이 좋아진다", "AI가 더 잘 알아듣는다".

## 니치

입력측 토큰 절감은 이미 붐빈 시장이다 — LLMLingua, leanctx, claude-shorthand, kompact, llmtrim. **그런데 전부 기계가 조립한 페이로드를 다룬다**: RAG 컨텍스트, few-shot, 스택 트레이스, MCP 스키마, 대화 이력, 코드베이스 덤프. 형태는 프록시·SDK·훅이다.

사람이 GUI 입력창에 지금 타이핑하는 문장을 건드리는 도구는 없다. 진입장벽이 OS 접근성 API이기 때문이고, WDS는 그걸 이미 만들었다. **자산은 51개 단어 사전이 아니라 살아 있는 사람 타이핑에 붙는 OS 레벨 훅이다** (승인 UI + fail-closed 재검증 포함).

경쟁 위협: Apple Intelligence Writing Tools(OS 기본, 무료, 단 selection 기반 수동 호출 + rewrite 방식), Grammarly for Mac(같은 AX 경로를 이미 점유, 단 감정 토큰 삭제는 안 함).

## 의도적으로 미룬 결정

이걸 "빠진 것"으로 보고 다시 제안하지 말 것. 이유가 있다.

- **한국어 우선.** 본인이 직접 써보며 피드백하기 위한 프로토타입이다. 영어 확장은 예정돼 있고 당연히 할 것이다.
- **Developer ID 서명·공증 안 함.** 지금 ad-hoc 서명이라 `spctl -a`가 reject하고 본인 머신 빌드로만 쓴다. 아직 본인도 못 쓰는 케이스가 있는데 배포할 이유가 없다. 어휘가 좁아서 남에게 주면 "아무것도 안 뜬다"가 될 가능성이 높다.
- **터미널 경로 resolver는 pass-through 스텁.** 전송·인증·검증은 완성. 앱의 수락 UI가 미구현이라 Zsh에서는 아무것도 지워지지 않는다. README에 명시돼 있다.
- **Claude Code/Codex CLI 내부 TUI 미지원.** `forkpty` 기반 `wds-run`을 의도적으로 만들지 않았다. PTY 바이트만으로 IME·커서·편집 버퍼를 무손실 복원할 수 없고, 불완전한 복원은 엉뚱한 범위를 지우거나 Enter의 의미를 바꾼다.
- **AI 문맥 판정 기본 Off.** 원격 호출과 토큰 사용이 정확히 0이어야 한다.
- **웹 프로토타입 은퇴.** `web-prototype-v0` 태그에 보존하고 main에서 제거했다. 복구: `git checkout web-prototype-v0 -- src index.html styles.css scripts/serve.mjs scripts/context-judge.mjs`

## 현재 실제 상태 (실측 확인됨)

동작 검증된 것: AX 읽기 → 정확 범위 삭제 → 오버레이 렌더. TextEdit 대상 end-to-end로 확인했고, fail-closed 4종(digest·pid·range location·range length 불일치)이 모두 원문을 유지한다.

실제 제약 두 개:
1. **탐지 어휘가 좁다.** 51개 문자열, 실질 한국어 욕설 1개 계열(시발/씨발/ㅅㅂ/ㅆㅂ) + 강조어 2개(존나/ㅈㄴ) + 도입부 15개. 영어 욕설은 0개(hesitation marker만 있음). 대부분의 실제 초안에서 아무것도 안 잡힌다. 기계는 정확한데 발동 빈도가 낮다. **여기가 병목이다.**
2. 터미널 경로 미완성 (위 참조).

## 열린 질문

**confidence 축이 새 논지와 어긋나 있다.** 현재 `confidence`는 "지워도 의미가 안 변하나"(삭제 안전성)를 재는데, 새 논지가 필요로 하는 건 "안 지우면 결과가 얼마나 틀어지나"(해석 오염도)다. 두 축이 반대로 정렬돼 있다.

| 후보 | confidence | 해석 오염도 |
| --- | --- | --- |
| 중복 쉼표 | 0.98 (최고) | 거의 0 |
| 문두 `씨발 ` | 0.94 | 높음 (거절·방어 유발) |
| 강조어 `존나 ` | 0.885 | 높음 (스펙으로 오독 가능) |
| 도입부 `음, ` | 0.86 | 거의 0 |

제안: `interpretiveImpact` 같은 축을 하나 더 두고 패널 우선순위를 두 축 조합으로 정한다. `CurrentDraftDeletionReason`이 이미 5종이므로 reason별 상수만 붙이면 되고 `CurrentDraftAnalyzer` 구조 변경은 불필요하다. 아직 미구현.

**성공 기준이 측정 가능해졌다.** 같은 요청을 노이즈 있는/없는 버전으로 각각 N회 돌려 거절률·감정 관리 문구 포함률·요청 이행률을 비교하면 니치 논쟁이 의견에서 데이터로 넘어간다. 미실행 (`claude` CLI 미로그인, `ollama` 모델 없음).
